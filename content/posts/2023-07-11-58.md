| **라벨링 도구** | **[API 개발]** 단순 API 개발 진행중에는 큰 문제가 없었다. 그리고, 다른 부서와 API를 연동하면서 여러 변동 상황에 취약해졌고, 각자의 API 및 관련 개발정책의 변경사항이 있을때, 서로간의 공유와 커뮤니케이션이 얼마나 중요한지 깨닫게 되었다. 여러변 변경사항이 발생할때, 너무 휘둘렸다. > 뭐, 이 부분은 관련 TF채널에서 좀 더 소통을 강화할 필요가 있겠고, 구두로 전달하기 보다는 업데이트 된 명세서로 소통할 수 있도록 정리하자.  **[슬슬 대두되기 시작한 서비스의 속도문제]** 첫번째, 우선, 바인딩할 데이터의 물리량이 늘어났다.. 수천, 수만장의 이미지를 로드할때, 물리적으로 시간이 오래걸린다. 이럴때, 비동기로 처리하는것 외에는 방법이 없을까..? > 우선 전체 데이터의 크기를 먼저 전달받고, 바인딩 진행상황을 프로그래스로 표현한뒤 진입 제한하는 방안으로 처리는해야겠다. 다만, 궁극적으로 속도 해결 부분에 있어, 고민이 필요하다. PMS쪽과 개선방안에 대해서 한번 더 논의해보자.  두번째, 이미지 다운로드 URL을 받아서, httpresponse를 진행할때, 속도가 생각보다 느리다.  > 이미지 URL형태가 아니라, 바로 띄울 수 있는 형태로 전달할 수 있도록 구조를 바꿔보자. 이 부분도 PMS쪽과 다시 한번 협의해보자. > 그리고 전체 API들에 대해서 속도개선이 필요한 부분을 추려서 개선방안을 강구해보자.  [서버간 통신 매커니즘과 innerG/W Architecture에 대해서 정리하자] 이 부분에 이해가 약해서, 이번에 좀 해맨 부분이 있다.   1) WAS와 HA, 로드밸런서 부분에 대한 좀 더 정확한 이해를 위해 관련 내용을 공부하고 포스팅하자 2) innerG/W 구조와 사용방식에 대해서 회사 wiki에 정리하자 3) OAuth, JWT(JSON Web Token) 등의 인증 및 권한 부여 방법 이해에 대해서 좀 더 공부하고 포스팅 하자. 4) 쿠키에 담긴 세션정보를 내가 받는 부분까지의 구체적인 프로세스를 다시 살펴보자. 5) 운영기 WAS와 DB연결 상태 확인 방법에 대해서 다시 살펴보기  6) 운영기에서 쿠키정보가 안넘어온다는것을 확인한 루트에 대해서 살펴보기 |
| **당뇨CDSS** | **[첫 회의 잡기가 너무 힘드네]** 지금 데이터 EDA를 진행하고, 기초 시각화 자료를 뽑기 위한 통합 데이터 생성에 시간이 너무 많이 걸리고있다. 우선, 기획분은 섣불리 가져갔다가, 그대로 확정될 수 있고, 팀내 단독으로 기획분을 제시하는것이 무리가 있으므로, 우선 통합 로직의 합리성에 대한 검증과 관련 시각화 내용을 보여드리고, 데이터 처리 방식에 대한 확신을 얻는것이 중요할 것 같다. > 우선 데이터 통합로직에 대한 내부 합의와 시각화를 완료하고 빨리 회의를 잡자 |
| **개인공부** | **[알고리즘 공부는 계속 꾸준히 하자구]** 확실히, 알고리즘을 계속 공부하는게 업무에 바로바로 적용되면서 코드 개선에 큰도움이 되고있다. 비슷한 형태의 코드만 돌려쓰는것이 아니라, 계속 새로운 방향으로 고민해보고 적용해서 개선하게끔 생각하게 되는 장점이 있다. 그리고, 처음부터 클린하고 효율적인 형태의 코드를 짜기 위해서도 알고리즘은 계속 난이도를 높여서 공부해나가는게 좋겠다.  **[모델개발에 대해서 좀 더 개인 과제를 만들어서 진행하는것이 필요할듯 싶다]** 민지씨와 얘기했던 것 처럼, 서비스 내부에서 AI를 통해 개선을 시도해볼만한 컨텐츠 발굴을 계속해야겠다. 그리고 3개월 내 결과물을 확인할 수 있을 정도의 분량 및 난이도면 좋겠다. 젠데스크 개선방안에 대해서 민지씨와 얘기해보고 프로젝트를 진행해보도록 하자. |
| **정리** | 아마, 다음달에는 부서개편이 있을 예정이고, AI모델의 실서비스 적용과 개발에 업무 초점이 강화될 예정이다. 다음달은 슈퍼북 고도화 모델개발, 당뇨CDSS관련 시각화 마무리 및 회의 진행, 라벨링도구 개선 세가지를 조금 촘촘한 일정으로 진행하고, 이에 대한 **상세계획을 세우자.** 그리고, 알고리즘과 개인 Task도 진행할 수 있도록 할 것. |
